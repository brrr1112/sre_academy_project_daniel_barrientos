deploy.sh performs, in order:

  1. docker load -i <tar> and read the image name (sre-task-manager:main-e2e9106-arm64).
  2. minikube image load sre-task-manager:main-e2e9106-arm64.
  3. kubectl apply -f kube/namespaces.yaml (application, monitoring).
  4. Create the Secrets alertmanager-secrets (from the environment variables, placeholders if unset) and grafana-admin (random password).
  5. Apply one directory per component: kube/prometheus/, kube/alertmanager/, kube/grafana/, then kube/app/ (with the image name substituted).
  6. kubectl rollout status on every Deployment, then print the endpoints.

5. Access and Port Forwarding from macOS

On macOS with Docker driver, the Minikube VM/container network (192.168.49.2) is not directly routable from the host. In addition, applications are bound to Pod IPs inside containerd namespaces, which prevents direct kubectl port-forward from reaching them via loopback.

Method 1: Direct SSH NodePort Tunnel (Recommended - Preserves exact NodePorts)

This forwards all 4 Kubernetes NodePorts 1:1 to 127.0.0.1 through Minikube's SSH bridge in a single background command:

# 1. Extract the Minikube SSH Key and dynamic SSH port on the host
SSH_KEY=$(minikube ssh-key)
SSH_PORT=$(docker port minikube 22/tcp | head -n 1 | sed 's/.*://')

# 2. Launch background SSH port forward for all 4 services
ssh -i "$SSH_KEY" \
  -o StrictHostKeyChecking=no \
  -p "$SSH_PORT" \
  -N -f \
  -L 30007:127.0.0.1:30007 \
  -L 30093:127.0.0.1:30093 \
  -L 30030:127.0.0.1:30030 \
  -L 30090:127.0.0.1:30090 \
  docker@127.0.0.1

To stop this tunnel later:

pkill -f "ssh.*30007:127.0.0.1:30007"

Method 2: Minikube Service command (Foreground terminal)

minikube service sre-task-manager-service -n application   # Opens http://127.0.0.1:<port>
minikube service alertmanager             -n monitoring
minikube service grafana-service          -n monitoring
minikube service prometheus-service       -n monitoring
